# Native DSH capability audit

Snapshot: 2026-11-08. This is a partial source-and-document review, not runtime certification. The configured baseline is DSH 0.2.1-rc.2. The npm `latest` response was 0.2.2-rc.1, a prerelease; the upstream source references below are pinned to master commit `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`, not necessarily that release. GitHub's [latest stable release endpoint](https://api.github.com/repos/deepseek-ai/deepseek-harness/releases/latest) returned 404 on this date. The [npm package version list](https://registry.npmjs.org/%40deepseek-ai%2Fdsh) contained 42 versions, none matching a stable `major.minor.patch` version; this does not rule out an unpublished or non-npm stable tag. No code removal or measured performance improvement follows from this review alone.

## Prioritized limitations and local status

This is a partial ranking by potential user impact, not a claim that every native limitation has been audited. Evidence is source or documented behavior at the snapshot date, not proof of current live performance.

| Priority | Limitation                                                                                                                      | Local status and remaining gap                                                                                                                                                                                                                                                                                            |
| -------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1        | Large session search can block the Host: the installed SQLite backend uses synchronous database work and corpus reconciliation. | **Mitigated, not equivalent:** [session search](../plugins/@dshfiles/session-search/README.md#current-limitations) moves indexing to a worker. Broad search excludes archived sessions, some filters are refused, and newest events appear after log commit. Historical measurements are not current upstream benchmarks. |
| 2        | Process-local jobs do not survive a Host restart as running work.                                                               | **Partially addressed:** [background jobs](../plugins/@dshfiles/background-jobs/README.md) keeps lifecycle history, not old output or execution. [Project checks](../plugins/@dshfiles/project-checks/src/durable-task-runner.ts) adds recovery for its own queued actions, not arbitrary jobs.                           |
| 3        | Native Git worktrees are not JJ workspace isolation and integration.                                                            | **Locally addressed with a gap:** [JJ integration](../plugins/@dshfiles/jj-integration/README.md#the-thread-workspace-control) supplies JJ workflows, but its queued integration requests and notices are lost on Host restart.                                                                                           |

## Checked against the 0.2.2 release candidate

The following observations are from the `dsh-v0.2.2-rc.1` tag, not master. They establish documented or source-level behavior, not compatibility with our profile:

- Its [subagent contract](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.1/packages/subagent/subagent/README.md) permits direct parent/child model messaging, not the wider tree-peer messaging observed on later master. It documents process-local residency, no durable parent mailbox, no replay of accepted-but-unlogged prompts and one-shot external children.
- Its [OTel contract](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.1/packages/telemetry/otel/README.md) describes consumer-owned redaction and best-effort, memory-only reporting without a durable outbox.
- Its [session controller](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.1/packages/api/session-controller/src/index.ts) exposes separate event, state and projection observation. That alone does not prove parity with the local bounded history or browser filtering.

### Candidate: session-list and search consolidation

The candidate [session controller](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.1/packages/api/session-controller/README.md) documents cold header and projection-cache reads plus a summary-key subset. This may overlap with part of the [local controller's](../plugins/@dshfiles/session-controller/README.md#local-delta) list optimization, but its key set and invalidation behavior are not yet proven equivalent. Native [history](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.1/packages/api/session-controller/src/history.ts) still passes full events; the local [browser filter](../plugins/@dshfiles/session-controller/src/browser-event.ts) removes large replay blocks. Other local model, retry and routing contracts also remain. Compare response size, ordering, cold/live transitions and real journeys before removing any delta.

The candidate [SQLite search](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.1/packages/session-query/session-query-sqlite/src/index.ts) reconciles live sessions synchronously on search. The [local worker](../plugins/@dshfiles/session-search/README.md#current-limitations) trades freshness and some broad-search coverage for off-Host incremental indexing. A replacement needs a same-corpus performance, recall, filter, restart and rollback comparison. Projection registration also changes in the candidate release; migrate lifecycle ownership and test seeded histories rather than assuming old synchronous registration semantics.

### Team, workflow and commands

The tagged [0.2.1 Team package](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-rc.2/packages/experimental/agent-team/README.md) persists task and roster state in the lead's log but describes shared working directories and lacks cross-process coordination and worktree isolation. That is not the project-scoped persistence, attachments, sync and lease contract of the [local backlog](../plugins/@dshfiles/backlog/src/backlog-db.ts). Retain it unless a narrower shared-checkout coordination workflow needs a bridge.

The [native workflow tool](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.1/packages/workflow/tool-workflow/README.md) supports background execution using native jobs, but a running workflow is not a durable resumable workflow. [Project automations](../plugins/@dshfiles/project-automations/README.md) instead stores project triggers and starts Sessions; neither replaces the other. Native slash commands are already used by [JJ integration](../plugins/@dshfiles/jj-integration/src/host.ts); the [command palette](../plugins/@dshfiles/command-palette/src/contributed-commands.ts) composes client actions with different availability and shortcut semantics. No removal is established.

### Candidate: native session wait

The installed [0.2.1 controller](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-rc.2/packages/api/session-controller/src/index.ts) does not expose the newer wait method. The [0.2.2 candidate](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.1/packages/api/session-controller/src/state/controller.ts) is not a drop-in replacement for our [wait adapter](../plugins/@dshfiles/session-controller/src/sessions-host.ts): it can return immediately for input-required, observes cold sessions and has different missing-session and timeout semantics. The local API waits for both agent idleness and empty inboxes and permits timeout zero. Its [MCP consumer](../plugins/@dshfiles/mcp-endpoint/src/mcp-tools.ts) relies on this contract. Any migration needs queue, question, timeout, cold-session, cancellation and agent-replacement tests; a naive retry on input-required could spin. No reduction is established.

### Goal authority and feedback

The [0.2.2 goal authority](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.1/packages/goal/tool-goal/src/authority.ts) recognizes direct user messages; the local [goal authority](../plugins/@dshfiles/goal-tool/src/native/authority.ts) additionally checks settled, answered user-question replies before accepting them. Do not remove that fork until native authority and its turn-boundary and argument semantics have parity. The [goal stall guard](../plugins/@dshfiles/goal-stall-guard/src/host.ts) also detects consecutive empty rounds, while its [continuation tool](../plugins/@dshfiles/goal-stall-guard/src/goal-continuation.ts) supports bounded extensions; evidence supplied for completion remains model judgment rather than independent verification.

Native [message feedback](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-rc.2/packages/feedback/message-feedback/README.md) records ratings of finalized assistant messages. Local [annotations](../plugins/@dshfiles/annotations/README.md) instead support element/source feedback and revision-aware resolution; [parent feedback](../plugins/@dshfiles/agent-questions/src/parent-feedback.ts) anchors child feedback to Markdown revisions. These are distinct contracts. The local annotation store is in-memory authoritative and catches persistence failures; do not assume native feedback's log durability applies to it.

### Jobs and telemetry boundaries

The [native jobs registry](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-rc.2/packages/jobs/jobs/README.md) is already the engine for [background jobs](../plugins/@dshfiles/background-jobs/src/live.ts). The local board adds cross-session views, multi-job waiting and [bounded lifecycle history](../plugins/@dshfiles/background-jobs/src/history.ts); historical output and execution are not durable. [Project checks](../plugins/@dshfiles/project-checks/src/durable-task-runner.ts) separately owns a durable queue and recovery, so a process-local job registry is not a replacement for that contract.

Native [OTel reporting](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-rc.2/packages/telemetry/otel/README.md) is outbound and best effort. The local [receiver](../plugins/@dshfiles/traces/src/receiver.ts) accepts OTLP traces, logs and metrics, and its [repository](../plugins/@dshfiles/traces/src/trace-repo.ts) stores and queries them. These opposite directions are not interchangeable. An outbound adapter could be compared separately, but supported signals, retries, privacy and loop prevention need verification first.

### Candidate: conversation and tool rendering

The installed [conversation registry](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-rc.2/packages/client/ui-conversation/README.md#conversation-assembly) already supports definitions and turn publication. [Turn summary](../plugins/@dshfiles/turn-summary/src/turn-activity-node.ts) uses that contract rather than maintaining an independent subscription; its summary and changed-files handling remain local. Deriving its state from existing native tool nodes is only a candidate: test nested calls, replay, partial history and performance before claiming a reduction.

[Tool metadata](../plugins/@dshfiles/tool-meta/src/tool-call-tree.tsx) wraps the tool ledger to supply an additive per-call frame; [background jobs](../plugins/@dshfiles/background-jobs/src/client.tsx) consumes its sections. The installed [native keyed tool-view contract](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-rc.2/packages/client/ui-tool/README.md) does not itself establish that additive frame. [Test runs](../plugins/@dshfiles/test-runs/src/client-entry.tsx) already registers a keyed bash view and retains a fallback for other commands. Do not remove either plugin without equivalent frame, fallback and disposal behavior.

### Compaction, MCP and file safety

[Upstream master compaction](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/compaction/compaction-basic/README.md) describes a single summary request with indivisible-unit limits. Local [context compaction](../plugins/@dshfiles/context-compaction/README.md) adds bounded chunking and overflow handling. Compare the exact release's hooks and overflow tests before removing that extension.

The [master MCP manager](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/mcp/mcp-manager/README.md) documents management and status but not OAuth; local [MCP servers](../plugins/@dshfiles/mcp-servers/README.md) includes OAuth, secret references and local helper lifecycle. A future compatible release might replace a narrow lifecycle adapter only after migration, shutdown and OAuth parity are tested; master is not an installed capability.

[Master file observation](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/fs/fs-observation-policy/README.md) documents a default-disabled guard and per-session observations. Local [apply patch](../plugins/@dshfiles/apply-patch/README.md) has its own read-before-write, atomic replacement and ambiguity behavior. Test observation defaults, stale writes, concurrent creation, ambiguity and sandbox boundaries on the exact candidate profile before changing either safety contract.

### Session recovery and portability

The candidate [checkpoint policy](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.1/packages/session/session-checkpoint-policy/README.md) flushes before dispatch boundaries; it does not make external side effects exactly once, and a crash can leave their outcome unknown. Candidate [JSONL persistence](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.1/packages/session/session-persistence-jsonl/README.md) describes torn-tail recovery and migration without automatic downgrade. Verify old and forked logs, interrupted writes and rollback on isolated copies before upgrading.

Local [session undo](../plugins/@dshfiles/session-undo/README.md) combines session forks with separate file snapshots; it is not a substitute for a durable dispatch checkpoint or a crash-atomic transaction. Candidate [session export](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.1/packages/session-query/session-log-export/README.md) supports browser ZIP and Markdown, while local [thread transfer](../plugins/@dshfiles/thread-transfer/README.md) imports and exports a portable bundle with different descendant and attachment behavior. Preserve both until their specific workflows and privacy properties are compared.

## Upgrade gates

The [0.2.2-rc.1 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-rc.1) describe Node and Cordis changes, async projection registration, tool execution changes and a changed SSH helper protocol. They also describe changed file-observation and Web Fetch defaults. Verify equivalent protection and deployment egress policy rather than assuming security defaults match. The release summary starts after our pinned release: [0.2.1-rc.3](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-rc.3), [rc.4](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-rc.4) and [rc.5](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-rc.5) also require review for migration-relevant changes.

Before removing a local implementation, boot an isolated profile with the exact candidate release and no private state; compare authorization, replay and ordering, queue limits, cold history, crash recovery, browser interactions and representative latency. Change one adapter at a time and retain a tested rollback path. Concrete upstream requests include bounded browser-safe session events and projections, additive chat/tool slots, off-thread incremental search and explicit durable delivery/lease contracts.

## Remaining evidence

This review did not cover all official documentation or local plugins, determine the latest stable release, run the 0.2.2 profile, benchmark current upstream, or perform migration and rollback drills. Master-source behavior is not proof of release or installed-runtime behavior. Keep the corresponding backlog investigations open until those gaps are resolved.
