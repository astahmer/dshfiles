# Community plugin decisions for #220

Source review for [#220](https://github.com/astahmer/dshfiles/issues/220), 2026-11-23. Local comparison: [dshfiles `4c0774ed`](https://github.com/astahmer/dshfiles/tree/4c0774edaf0995d0639d235e725a1c977622e62f), stock DSH `0.2.2-rc.2`, `@deepseek-ai/cordis` `4.1.0`, Node `24.11.1`. Local links name implementation owners, not proof of live activation; [the Web seed](../profiles/web/package.json) is not a dump of anyone's writable profile. The [older catalog audit](community-plugin-audit.md) is a `0.2.0-rc.2` snapshot, not compatibility evidence here. Decisions follow [Adopt, port, or build](../AGENTS.md#adopt-port-or-build). The [Capabilities Hub](../plugins/@dshfiles/capabilities-hub/src/hub-model.ts#L52-L82) routes to the owners and distinguishes skills, MCP tools/credentials and executable plugins; it does not search or install the catalog itself.

## One decision per reference

“Source” means inspected public code/manifest at the linked revision, not a runtime test. Peer admission only means a declared range includes the baseline; “no DSH peer” means no version contract, not broad compatibility. Product availability, marketplace descriptions and upstream claimed compatibility are not independent test results.

### Existing desktop options

- **macOS:** Stock `@deepseek-ai/dsh-cua-bundle@0.2.2-rc.2` [ships off by default](https://cdn.jsdelivr.net/npm/@deepseek-ai/dsh-cua-bundle@0.2.2-rc.2/README.md). Its [version-pinned patch](https://cdn.jsdelivr.net/npm/@deepseek-ai/dsh-cua-bundle@0.2.2-rc.2/cordis.patch.yml) mounts an exclusive provider registry, a macOS-only provider scoped to PTC sessions, and the CUA permission UI. The registry alone is not a driver. Enabling the bundle is not consent: macOS Accessibility and Screen Recording require human approval, and the bundle documents separate application-access decisions.
- **Linux:** The [repo guide](computer-use.md#L63-L93) documents a separate, opt-in `computer-use-linux` stdio MCP connection with no default server and shell disabled. It needs the intended graphical Host session and compositor-specific support; discovery alone does not establish capture, input or approval behavior. The guide's [historical test](computer-use.md#L147-L164) was on DSH 0.2.1-rc.2, not evidence of activation or qualification for this audit. Neither desktop option was enabled or exercised here.

## How marketplace search works

- **Public site:** [Browse](https://dshmarket.com/browse/) is prebuilt catalog HTML. The [pinned browse template](https://github.com/dsh-market/dsh-market/blob/ed2acb5caf10f1acd598b2faee263a1393a8d9ae/site/browse-template.html#L82-L101) filters existing rendered rows with trimmed, lowercased substring matching and hides empty categories. No server query or login is needed for that filter. The cited [detail URL](https://dshmarket.com/p/hyzyn/dsh-plugin-kit--packages-search/) serves a handoff to [the awesome-dsh-plugin listing](https://awesome-dsh-plugin.com/p/hyzyn/dsh-plugin-kit--packages-search/); the [pinned directory record](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin/blob/550c19ec0a24a9d0cb2c064f05b4127b8c3943fd/data/plugins/hyzyn__dsh-plugin-kit--packages-search.yml) identifies `@hyzyn/dsh-search`.
- **In DSH, ordinary keyword search:** the [seed](../profiles/web/package.json#L108-L120) declares `dshmarket` `^1.66.14`, not the live installed version. The [1.66.14 npm metadata](https://registry.npmjs.org/dshmarket/1.66.14) pins its source revision; [that matcher](https://github.com/dsh-market/dsh-market/blob/30f30ed419275b43d776380b32fa3a06e1b39d9b/src/client/market-data.ts#L461-L598) normalizes and scores names, npm identities, descriptions and categories, then applies list filters and a secondary sort. [Current public 1.80.1 source](https://github.com/dsh-market/dsh-market/blob/ed2acb5caf10f1acd598b2faee263a1393a8d9ae/src/client/market-data.ts#L743-L993) also supports curated synonyms below literal matches. The compatible-only filter is not a compatibility oracle. The declared `dsh-settings` prerelease range in the seed version does not admit rc.2; wiring in the seed is not proof it loads. Hub [handoff code](../plugins/@dshfiles/capabilities-hub/src/plugin-market-page.tsx) opens the market section only when registered; the native Plugins page owns inventory and the external market owns its catalog.
- **In DSH, optional model-assisted search:** the [public site](https://dshmarket.com/#features) advertises AI search and `/find-plugin`. In [1.80.1 source](https://github.com/dsh-market/dsh-market/blob/ed2acb5caf10f1acd598b2faee263a1393a8d9ae/src/find-plugin.ts), the Host recalls at most 30 candidates from catalog metadata, then the configured model ranks a shortlist. The [client switch](https://github.com/dsh-market/dsh-market/blob/ed2acb5caf10f1acd598b2faee263a1393a8d9ae/src/client/AiSearch.tsx#L17-L46) is off by default and the feature spends tokens when invoked; the request, candidate descriptions and, if allowed, installed/favorite hints can enter the model prompt. Not the website filter, not checked on the seed version, and not invoked here.
- **Stock Discover is another option:** the [market's public docs](https://dshmarket.com/) advertise the format-1 index for DSH Discover and its `plugin_market` tool when that stock bundle and index source are configured. The [index builder](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin/blob/550c19ec0a24a9d0cb2c064f05b4127b8c3943fd/scripts/lib/market-index.mjs) maps catalog records into the format; the installed [stock bundle](https://www.npmjs.com/package/@deepseek-ai/dsh-experimental-plugin-market-bundle/v/0.2.2-rc.2) declares the Host index service and the Discover client, but the [Web seed disables the tool row](../profiles/web/cordis.patch.yml#L272-L277). Index presence isn't proof any index source is configured. The index covers plugins, not local Sessions or settings.

**Reproducible public check:** GET [Browse](https://dshmarket.com/browse/), parse its `<li>` text and apply the template's case-insensitive substring predicate to `HYZYN/DSH-PLUGIN-KIT#SEARCH` (found the target row) and `no-such-plugin-220-zxqvf` (no rows). Independently, GET the [site index](https://dshmarket.com/index.json) and [npm CDN index](https://cdn.jsdelivr.net/npm/dsh-plugin-catalog/index.json); each had `format: 1`, contained the exact package name `@hyzyn/dsh-search` in `.plugins[].name`, and did not contain the synthetic miss. The two URLs returned different snapshots on the review date, so don't assume simultaneous freshness or use catalog size as a test. These checks used public data and local predicates only (no forms, authentication, code from the pages or model calls); they are not tests of an installed market.

## Before any adoption or port

No install or activation is recommended by default. Prioritize existing owners: transcript notes already work in Chat, browser feedback belongs to Annotations, docking to Workbench, cards to HTML Render, and plugin discovery to Plugins/Market. The two conditional candidates fill different gaps: actual `.op` interoperability and multimodal evidence for a genuinely text-only route.
