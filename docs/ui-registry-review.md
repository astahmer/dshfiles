# UI registry review: HextaUI and affectUI

**Decision for [upstream #212](https://github.com/astahmer/dshfiles/issues/212): do not add a registry component.** The strongest free candidate, affectUI Tree View, identifies a real keyboard gap in the editor, but it is a static-tree renderer, not a drop-in for the editor's lazy, watched workspace tree. Fix that behavior at the owner if pursued; don't add a second tree to the kit on the strength of a demo.

## Evidence and availability

Review date: 2026-11-24. dshfiles baseline: [`4c0774ed`](https://github.com/astahmer/dshfiles/tree/4c0774edaf0995d0639d235e725a1c977622e62f), including the [checked-in Web seed](../profiles/web/package.json), not a live-profile inspection. The old [HextaUI plan was folded into the owning docs](https://github.com/astahmer/dshfiles/commit/f24f5b4b48f005f74e253d7a2ac2fbe75d808dd1); the [kit's prior review](../plugins/@dshfiles/plugin-ui/README.md#design-references) already covers sidebar, settings, API keys, models, notifications, billing and several chat blocks. The [community plugin audit](community-plugin-audit.md#3-borrow--capabilities-we-do-not-have-and-should) records adjacent transcript/disclosure and diff tooling, not a missing UI library. The [prior UI handoff](ui-backlog-handoff-2026-11-08.md#c-the-what-needs-me-surfaces--the-one-coherent-ux-project-6) identifies the Inbox owner; the current code and docs below supersede the handoff's snapshot.

## What would change the decision

Start with one real problem and one owner, not a gallery-only component. For editor keyboard navigation, first reproduce in the real File Tree; retain lazy listing and cancellation, then prove a single Tab entry, arrow expand/navigate, typeahead, Enter-to-open, and focus recovery after collapse or refresh. At 390 px in scratch WebKit, check named touch targets of at least 44px and long paths without hover or overflow. Under reduced motion, the same operations must stay immediate and legible. Promote a shared primitive only if another real consumer needs the same contract.

If an MIT item does later earn a place, follow the [kit's shadcn workflow](../plugins/@dshfiles/plugin-ui/README.md) with the pinned CLI and a local, statically inspected registry item. Check the exact source and license notice, dependencies, CSS, file destinations and URLs first; no upstream script, remote production asset or whole-registry install. Use the kit tokens and shared style owner, and verify the real consumer as well as its gallery entry. This review inspected docs, source and public registry metadata only; no registry script, browser interaction, scratch or live DSH instance, or paid call was used.
