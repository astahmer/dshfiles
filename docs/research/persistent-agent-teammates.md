# Persistent agent teammates: Kiroshi and Rakazo vs dshfiles

**Decision (2026-11-23):** Keep ordinary DSH Sessions as the execution and transcript owners. The best ideas are easier ways to find what agents produced and see whose response is needed. Start in [#164] and [#181], not with two new products or a new agent runtime. The one distinct candidate after that is durable receipts for one project-local file change input, reusing stock file observation, only if someone has a real workload that a schedule or signed webhook cannot serve.

## Scope and evidence

This is one read-only comparison for upstream [#121] and [#166]. Both were open with no comments when checked. Competitor claims refer to the source snapshots below, not to the latest packaged release. **Documented** means first-party description; **source/test case** means the linked code or test was inspected, not executed here. No product workflow was exercised for this report. Prior DSH tests and probes are labeled separately.

- **Stock** is DSH `0.2.2-rc.2` without the owned plugin layer. The pinned installed [Base][stock-base], [Web][stock-web] and [standard preset][stock-preset] configuration were used as sources, not the running profile. Stock has Sessions, presets, approval and filesystem/shell sandbox modes, subagents, [Agent Teams][stock-team] (off per new Session, not an optional bundle), a persisted Goal, and same-thread Schedule. In stock Web, transcript full-text search is opt-in and the sidebar Browser is disabled outside the Desktop profile. The optional stock voice and macOS Computer Use bundles are not web-seed defaults.
- **Seeded** means an owned bundle is listed in the checked-in [web seed](../../profiles/web/package.json#L112-L223) at [upstream main](https://github.com/astahmer/dshfiles/tree/4c0774edaf0995d0639d235e725a1c977622e62f), not that it is active, configured, or authorized on a live Host. The [web overlay](../../profiles/web/cordis.patch.yml#L104-L107) enables the Browser row. The [derived standard preset](../../profiles/web/cordis.patch.yml#L226-L247) wires the owned subagent fork inside the managed region at this snapshot; the [preset contract test](../../scripts/dsh-compat/standard-preset.test.mjs#L15-L20) confirms the location. Do not infer which preset an existing Session uses. An option within a seeded bundle can still be off (e.g. phone pairing). **Not seeded** means available separately, not missing from the repository.
- Kiroshi ([MIT][k-license]) is a local-first desktop app (macOS, Windows, Linux) plus an iPhone client for online Spaces. Its README documents Claude today, via the user's Pro/Max subscription or an Anthropic API key; prompts go to that provider. Local features are free; relay sharing and iPhone access are Pro ($15/user/month billed yearly or $20 monthly), free during the documented beta. The desktop Host must be open for a shared Space. No claims about actual subscriptions, packaged release parity or relay operation are made here ([README][k-readme], [relay design][k-relay]).
- Rakazo ([Apache-2.0][r-license]) is self-hostable, with a server and web, Electron and Expo clients. Bots remain available while the backend runs. The documented published-image default uses local Docker; provider-backed computers, voice, external memory, inbound email and managed integrations have separate deployment/account prerequisites. Self-hosted app data does not imply local-only model or connector processing; check provider spend, workspace persistence and data egress separately ([README][r-readme], [storage][r-storage], [model setup][r-models]). Neither app was installed or run; no private histories, devices, accounts or live settings were read.

## Duplicate and evidence notes

- Checked the public [all-state issue index][issue-index], [open PR index][pr-index], relevant issue bodies and issue timelines. - **Still unknown:** packaged parity and real relay/cross-user permissions, cloud-provider behavior and costs, device handoff and voice behavior on hardware, tenant boundaries in a deployed system, and live-profile activation.
