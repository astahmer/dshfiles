## Resume here

Toolchain note: `tooling/dshx/pnpm-workspace.yaml` now sets `enableGlobalVirtualStore: false`, matching the guard `plugins/pnpm-workspace.yaml` already documents. Without it a forced reinstall puts the SDK's cordis in the global store links, and the E2E boot check refuses every profile with "different @deepseek-ai/cordis peer identities". If a reinstall ever reintroduces that error, check this setting first.

Ask the user to restart the live Host so the new engine build (poisoned-leaf fallback, bounded catch-up, fair scheduling, call cap) actually runs; until then the live process keeps the old engine and the frozen view. After the restart, watch the Explorer Pipeline tab: `viewThroughPos` should climb off 468 and `callsLastMinute` should sit at or below `rateLimitPerMinute`. Then decide whether to raise `summaryCallsPerMinute` / `catchUpBatchPerStream` to drain the ~16.5k-call leaf backlog faster, or leave the conservative default. Still open: capture real per-call token usage, resolve the unrelated full-plugin build failures, rerun the broad repository gates, and rerun the 100k-event benchmark on a quiet machine.
