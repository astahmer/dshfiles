# What we still lack compared to t3code

Compared against [pingdotgg/t3code](https://github.com/pingdotgg/t3code) at nightly tag
`v0.1.6-nightly.20261029.3892` (commit `08a463e29976617134de01e9341f898bc881d0eb`); t3code
paths below are relative to that tag. Our side is DSH 0.2.1-rc.2 plus `plugins/@dshfiles/*`.
t3code is a control surface for vendor agent CLIs (Codex app-server, Claude, Cursor, Grok,
OpenCode, Pi, ACP agents) with an Effect server, web, Electron and Expo apps; DSH runs its
own agent loop that plugins extend.

Only open gaps are listed. Closed rows keep their ID in the index at the end, pointing to
the doc that now owns the behavior, so references such as "C3 in t3code parity" still
resolve.

Resume here: pick an item from "Suggested order".

Deferred, each costly or needing a new client: B1 (an ACP client to drive Claude Code or
Cursor harnesses as threads), A9 (simulator/emulator devices, desktop SnapShots), A10 (Open
VSX themes, voice dictation), D4 (desktop app, background service, self-update). D5 (Effect
Schema RPC contracts) needs no action: dshx has an opt-in Effect layer.

C1 is nearly closed: GitLab merge requests link, watch and settle behind the forge port; creating one and self-hosted GitLab hosts are being fixed. The other forges are on demand, not planned. Review comments, reviewers, merge,
auto-merge, revert, bulk close and stacks remain separate forge-loop work.

## Suggested order

1. **C5** viewed marks and the forge loop's review verbs, now that GitHub creates, links, watches
   and settles, and GitLab does once its create and self-hosted fixes land.
2. **A3** `wait_for` and `resize` in preview.
3. **C4** stored review guides on top of pulls-review scopes.
4. **A2** MCP Apps, once a fork-or-proxy decision for the MCP client is made.
5. Finish **A8**'s snooze undo, section drag and drag-sweep bulk settle.
6. **B2** has a stated next step above; run it before planning the feature. **A5** is a recorded
   Host gap ([row 109](dsh-host-gaps.md#the-ledger)), not work to start.

What we have that t3code lacks: a plugin platform (dshx, Cordis bundles, owned plugins,
native forks), cross-thread memory, the backlog, jj-first thread workspaces, an in-app OTLP
receiver and trace viewer, persistent agents and agent communication, policies, and one
agent loop whose transcript survives a model or account switch.
