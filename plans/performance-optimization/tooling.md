## T01 — Read compact build dependencies, not complete source maps (P1, measured)

- [ ] Implement and verify.
- **Evidence:** [rebuild.ts:63–99](../../tooling/dshx/packages/dshx/src/checkout/rebuild.ts#L63-L99) synchronously reads/parses both bundle maps for every buildable plugin before knowing whether they matter. [Planning:113–164](../../tooling/dshx/packages/dshx/src/checkout/rebuild.ts#L113-L164) does this even for no changes; [execution:226–240](../../tooling/dshx/packages/dshx/src/checkout/rebuild.ts#L226-L240) repeats inventory. Six actual prebuilt-checkout calls with `changedFiles: []` read 74 maps / 53,913,303 bytes each; first 297.45 ms, five warm median 171.09 ms, zero selected plugins. [Raw samples](evidence/checkout-results.json).
- **Plan:** have the compiler emit a compact, versioned source-dependency manifest from actual retained modules, without embedded `sourcesContent`; regenerate it with bundles. Read/map only relevant package topology and dependencies; reuse one inventory through plan/execution where valid. Fast-path documentation/no-change cases while still detecting missing bundle outputs. Use asynchronous bounded reads for needed cold metadata if profiling justifies it.
- **Safety:** source maps remain debugging artifacts, not a new hand-maintained authority. Fingerprint input/output identities and conservatively fall back when the manifest is absent/stale. Preserve transitive workspace dependents, dshx output-to-bundled-source matching, unmapped-source restart conservatism, missing-artifact repair and final Host/client content hashes.
- **Checks:** extend actual checkout-sync/compiler tests for source-only, docs-only, new/deleted files, missing maps/manifests/bundles, shared stylesheet and dshx changes. Repeat the probe: no-op planning must read zero full source maps in the manifest path and produce the same selected/restart result. Record filesystem calls/bytes, cold/warm wall time and peak memory, not only a faster mean.

## Preserve / do not optimize blindly

- Host and client builds already run concurrently inside one dshx build; do not wrap them in another unbounded layer.
- Turbo task dependencies, a bounded root build concurrency of four, shared cache-directory helpers, generated browser input digests, focused test selection and documented force-run policy already exist.
- Browser journeys are serial deliberately because concurrent Host+Chromium loads were flaky; boot-only checks already use measured concurrency three.
- Tests with `cache: false` can depend on external binaries/runtime state. Do not enable global caching until all inputs and fresh-run semantics are proven; split deterministic tests only when there is a real stable boundary.
- Desktop uses the actual DSH renderer. Its small startup/Host lifecycle code was inspected; no supported high-confidence performance redesign was established. Retain process ownership and launch-token safety.
- Installed/native HMR polling and Host filesystem watch pooling belong to the documented Host boundary, not this register.
