documented in [the Effect guide](../../tooling/dshx/docs/sdk/effect.md) (its "Known follow-ups" section summarizes

Resume here: pick any row; none blocks the others. Done and removed: the dead `optmem-core` engine (deleted), the
workspace-status poll (now uses the tested `threadStatusPollMs`), the busy-read audit (only project-checks opens
SQLite with a zero busy timeout; every other store waits 5 s natively), and the startup HAR re-capture (the

cold thread open, now skipped for listed local threads; its remaining costs are rows 11–13), and the per-reference
`jj:` title lookups (now one `referenceTitles` Host request per render pass: a transcript with 40 `jj:` chips naming
13 references made 13–26 `referenceGraph` requests one after another, each of five or more jj reads, and now makes one request of one jj read per
reference, counted in `plugins/@dshfiles/jujutsu/src/chat-reference-links.test.tsx`). The page-load profile,
its fixes and their scratch after-numbers (`listBundles` 1,019 ms → `bundleLabels` 38 ms per load) are in
[docs/performance.md](../../docs/performance.md#startup-har-and-page-load-profile-2026-11-04).
