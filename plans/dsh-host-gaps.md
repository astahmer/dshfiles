# DSH Host gaps

A standing ledger of capabilities a dshfiles plugin cannot express on the installed
Host. This repo runs stock DSH and carries no core patches, so a need that no
supported dshx or plugin API can express is recorded here and stops at that
boundary. One row per gap.

**Every row carries a decision.** A gap without a verdict grows forever; the point
of the table is that each one is either ours to build, a named upstream ask we keep
a workaround for, or dropped. Behaviour, workaround and verification live in the
owning plugin's README — this file is only the decision register.

| Column   | Meaning                                                                                                                                                                         |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Layer    | `host` needs a Host verb, service, projection or event. `client` needs a client render/lifecycle seam. `core` is a native renderer or content pipeline.                         |
| Decision | `own` we build and maintain it ourselves, no upstream ask. `upstream` we keep a workaround and want the Host change. `drop` product answer is no; stop carrying the workaround. |

### Row 76 detail — answered native question form flashes back

Only a `continued` question can flash: `publishContinuedQuestions` creates a card solely for `continued`
projection rows, while an `open` row only updates a card that already exists. A pre-deadline submit answers
through the waterfall, never queues an Inbox reply, and closes exactly once.

1. Submitting a `continued` form answers over the Remote path, which splices a `user-question-reply` into the
   durable Inbox and withdraws the panel.
2. `ReactLoopInbox.claim` splices that reply out of the Inbox at the step boundary — several `await`s before
   `step()` appends the admitted `user/message` that settles the question in the `userQuestions` projection.
3. Across that gap the projection still offers the call as answerable while the Inbox no longer holds the
   reply, so reconcile called `cards.ensure(...)` and republished the editable card: reopen, then close on
   settle.

Fix (client-only, ~25 lines): remember the calls this Client answered through the Remote path until the Host
stops listing them, and create that card without claiming the composer seat. The panel stays withdrawn and the
card keeps its identity, so a discarded reply is still revealable from its tool row.

## Rich question answers — transport boundary (2026-10-23)

Decision: **upstream**, owned by `user-questions` / `agent-questions`, Host layer.

Question free-text answers (with or without offered options) should support
composer references and image/file attachments. Backlog has attachment previews,
paste/drop handling and mention completion, but reusing its UI does not make the
native answer transport attachment-capable.

Verified against installed DSH 0.2.1-rc.2:

- `@deepseek-ai/dsh-user-questions/lib/types/types.d.ts` defines
  `AskUserQuestionAnswerItem` as `{ id, selected: string[], custom?: string }`.
  The `user-questions/request` waterfall returns that same answer batch.
- `lib/typert.remote-client.d.ts` exposes `userQuestions/answer` with only that
  batch; there is no attachment or reference-content parameter.
- `lib/index.js` uses a strict per-answer projection schema, and
  `UserQuestionService.answer` creates a late reply containing one JSON text
  block. It does not attach image blocks or upload receipts to the message.

Required seam: an optional, validated answer-content/attachment contract shared
by foreground waterfall answers, continued-question RPC replies, durable
projection/review records and model-facing delivery. Preserve text-only defaults;
validate attachment ownership and bounds on the Host. References need supported
serialization into that content, not merely visually decorated text.

Stop here rather than showing an upload control that silently loses image
content, embedding base64 in `custom`, or sending an unrelated second chat turn.
Once that seam exists, extract stable attachment and reference-input pieces from
backlog at a shared client boundary and reuse them for both generic question
variants and cross-thread custom-answer fields. Ordinary settings, credentials
and other scalar fields must remain plain inputs. No core or installed-package
patch made for this request.

### Drafts ready to file: tracing (rows 78–82, 85)

One discussion, "Lifecycle events a tracing plugin needs", with one numbered ask per row. Each names the event or
hook, the payload, and what a plugin does with it today. Filing is a public post: the user decides when.

1. **Around-step hook (row 78).** A waterfall such as `agent/step(this, step, next)` that runs the step body inside
   it, like `tools/execute` and `llm/stream` already do for tools and model streams. Today `step/start`/`step/end`
   are post-commit events, so a tracer cannot make the step the active context; loop work between the model stream
   and the tool calls lands unparented.
2. **Paired question-wait events (row 79).** `user-questions/waiting { callId, timeoutMs }` when a timed
   `ask_user_question` returns `pending`, and `user-questions/answered { callId, outcome }` when its late reply is
   admitted. Today the wait is only inferable by folding the projection.
3. **Queued-at time for inbox messages (row 80).** A `queuedAt` on each message `agent/inbox/spliced` reports (or an
   `agent/inbox/queued` event). Today only the splice moment is known, so queue wait cannot be measured.
4. **Continuation resume event (row 81).** A session event when a stored quota continuation is resumed, naming the
   blocked turn, so block→resume becomes one span instead of two unrelated turns.
5. **Host-side user notification (row 82).** A Host service (`ctx.notify({ title, body, sessionId?, level })`)
   that the Web client renders as a toast/system notification, so a plugin can announce something with no plugin page
   mounted. Today a client overlay polls the Host for it.
6. **`traceparent` on native requests (row 85).** Let the browser Connection forward a `traceparent` header (or
   envelope field) on every RPC, and have native controllers (`session/follow`, `session/create`, `session/prompt`)
   expose it to plugin listeners, so a browser interaction and the Host work it starts are one trace.
