# DSH Host gaps — features waiting on a DSH patch or upstream

BB behaviours our DSH plugins cannot reproduce because the Host (or dshx) lacks a capability. Each is a
candidate for an upstream DSH request (this repo runs stock DSH and carries no core patches) or a dshx change. The product behavior
and current workarounds are documented in each owning plugin's README.

| Feature | Plugin | Missing capability | Possible route |
| Link an existing thread as a child; BB auto-handoff to the parent | thread-sidebar | No API to set or change a session's parent; no first-turn event hook | Patch the session controller to expose `setParent` + a turn-lifecycle event |
| Undo a cascade archive (preserve-child-threads) | thread-sidebar | No archive event hook | Archive event on the session controller |
| Configure sessions-first `@` autocomplete ordering | thread-sidebar | Stock `@reference` is one source that returns files before sessions; `source.order` only reorders groups, and plugins cannot rank or replace its candidates | Expose a native reference ordering preference or a candidate-ranker hook for files, sessions, subagents, and folders |
| Fast `@` session search | mentions | `sessionReferenceResolver.candidates` calls `sessionQuery.listSessions` for every keystroke; that rebuilds the session corpus, including `persistence.list()`, before filtering and ranking matches | Add an indexed/incremental candidate lookup or a revisioned session-header snapshot the resolver can cache across queries |
| File references in isolated thread workspaces | jj-integration, mentions | `jj_thread_isolate` creates a separate checkout and returns its path, but cannot change the Session's immutable creation `cwd`; `FileReferenceService.list(agent, ...)` and native file-resource resolution are rooted in that stale cwd, with no supported workspace-root override. Relative file chips can therefore point at a different checkout or fail to preview after isolation. | Let a Session's effective workspace root be updated/resolved by the Host and make file-reference discovery and resource resolution use it, or add an explicit validated workspace-root argument to both APIs. Do not emulate this in a plugin by guessing from tool output. |
| Fast thread-content search on cold persistent logs | command-palette | Stock `dsh-session-query-sqlite` accepts `persistedReadConcurrency`, but its stable-index observation awaits each cold persisted session-log read in sequence. With a large history, `sessions.search` can remain pending long enough that the palette appears stuck on “Searching thread content…”; changing the profile concurrency setting alone does not help because the provider does not use it in that path. **Measured 2026-10-18:** the index held 682 sessions while 83 stored logs (146 MB compressed, one of them 33 MB) were unindexed, and every search reconciles by cold-reading all of them before writing every event back through `node:sqlite` `DatabaseSync` in one synchronous transaction — an unbounded Host-event-loop stall, not just a slow palette, and each aborted keystroke leaves the index stale so the next one repeats it. | Use bounded concurrent cold reads while preserving the before/after persistence snapshot check, bound the write batch, and honor cancellation; cover with a large persisted-history regression in DSH |
| Crash-interrupted turn state on the Session list | thread-sidebar | `SessionSummary` and the client `SessionStatus` expose `running`, `blank`, `updatedAt`, and pending interaction, but no fact saying a persisted turn was closed as `interrupted` by crash recovery: core writes that `turn/end` only when the session is next resumed (`interruptedTurnClosers`) or synthesizes it in memory for read-only observers, so no list consumer can see it. Workaround: the plugin records every `turn/start` in a durable in-flight file, clears it on `turn/end`, and promotes what a dead process left behind into its own recovery store as `interrupted`. | A `SessionSummary`/projection field (for example `lastTurnEndReason` or `interruptedAt`) folded from the persisted log, so the list shows the crash state core already knows without plugin bookkeeping |
| Persistent `@` scope hints | mentions | `InputTriggerSource` offers either a source-name title or a candidate `section`; the latter only renders while that source has candidates, and `header` is only a drill breadcrumb | Add a non-actionable localized source subtitle/header rendered regardless of candidate count |
| Collapse viewed files, "only unviewed" filter, auto-mark on scroll | diff-viewed | Review tab shows one file; plugins only add toolbar buttons | File-list slot / filter hook in the review tab |
| Live MCP connection health ("Connected") | mcp-servers | DSH MCP client reports no connection status | Status events from `dsh-mcp-client` |
| Legacy SSE MCP servers | mcp-servers | DSH MCP client supports stdio + Streamable HTTP only | Add SSE transport to `dsh-mcp-client` |
| "Unify branches" prefilled thread | jujutsu | No API to start a session with a prefilled prompt | Session create option `initialPrompt` |
| Edit a queued message that has attachments | queue-reorder | `QueueAction.edit` is text-only and `updateQueue` replaces the whole content | Host edit that keeps existing attachment refs and replaces only text blocks |
| ⌘, / ⌘N shortcuts | shortcuts | No service to open Settings / start a session from a plugin | Expose those actions as commands |
| Open a thread at the turn and step a request produced | usage | `uiWorkspace.openSession` only selects a thread; the chat's `scrollToTurn` is private to its viewport | `openSession(target, { turn, step })` or a chat navigation service |
| Cross-thread input-needed question inbox and answer | agent-questions | The plugin now has a root-only `list_thread_questions` projection inventory and direct-parent durable question list, plus continued-native and child answer tools. Stock timed projections still omit exact deadlines and legacy-schema calls; the plugin derives an estimate from the logged call time and schema. Native child-Session forms are inspection-only because `userQuestions.answer` requires a live root and accepts continued calls only; open forms use the active answerer waterfall, queued replies are not projected before admission, and stopped roots cannot receive replies. `attachWait` claims a UI wait. | Add an exact non-claiming timer snapshot, legacy/child-form coverage, and a race/cancel-safe open-form broker or Host service; support safe answer delivery to stopped roots if that remains desired. Preserve direct-parent ownership for plugin questions; see [async-agent-questions](async-agent-questions.md) and F34/I11 in [reference-feature-additions](reference-feature-additions.md). |
| Usage of title generation and plugin side calls in history | usage | The session log keeps no usage for `session-title` calls and no record of plugin `llm.stream` calls, including memory digests; only a live `llm/stream` observer sees them | Persist a `llm/side-call` event with route, usage and finish in the session log |
| Literal `$…$` in chat text (prices, shell vars) | — (native markdown) | Native `parseGfmWithMath` uses `math()` with `singleDollarTextMath: true`, so single dollars render as math; no plugin seam over the markdown pipeline | Core: `math({ singleDollarTextMath: false })` (keep `$$…$$`) |
| Tool-call duration and timestamp | tool-meta | `tool.call.toolview` replaces the whole native card per tool and there is no additive per-call slot; the call/result times are already on the blocks (`time`, `callTime`). The plugin swaps the `conversation.chat.node` `tool-call` ledger entry's component for a wrapper that frames each `renderSlot('tool.call.toolview')` dispatch, and warns (console, journey) when that seam drifts | Core: an additive `tool.call.meta` list slot rendered beside each atomic call, or a decorator API for keyed entries |
| View an archived thread read-only | thread-sidebar | `dsh-client-ui-workspace`'s navigation reconcile calls `clearArchivedCurrent()` on every Session/Workspace list change, and opening a Session (its `mainView` retain) is such a change, so an archived thread is dropped from the main view right after it opens; the plugin can only retry and then offer Restore and open | Let the main view keep an explicitly opened archived Session (clear only when it was archived while open), or an `openSession(id, { allowArchived: true })` option |
| No blank Session until the first send | jj-integration | Selecting a Workspace on the New-thread screen creates (or reuses) a blank Session because the composer needs one; every destination change therefore costs a Session | A draft composer bound to a Workspace that creates the Session on first submit |
| Tab strip above every main panel | main-tabs | `AppFrame` (`dsh-client-ui-layout`, not exported) renders the `main` keyed slot straight into its centre column with no seat above it. A `root` shadow cannot re-declare `main` (`SlotCore.register` throws on a declared child), a keyed shadow cannot render the entry it shadows (props are composed privately per entry), and disabling `ui-layout` drops its module from the boot graph, so a wrapper cannot reuse its `apply`. Workaround: a portal node placed before the renderer's `[data-slot="main"]` outlet anchor, re-attached on frame changes, with a startup self-check warning and the `main-tabs.strip-mount` e2e journey | A root-scoped `shell.main.header` list slot rendered above `MainPanel` in the centre column |
| Settings as a main-view tab, search and plugin pages without a fork | settings-shell | Settings is a modal owned by `ui-settings-general` (`sidebar.settings`). Its pages are `settings.section` entries that only the declaring entry may `renderSlot` (`boundRenderSlot` in `dsh-client-ui-renderer`), a shadow cannot re-declare them, `SettingsRoot` is not exported, and disabling the row removes its client module. Workaround: `@dshfiles/settings-shell` ports the whole shell (0.2.1-rc.2) and switches the row off; a test and a boot warning flag a new upstream version | Expose Settings as a `main` panel (or a `settings.page` Factory any plugin can render), an observable `settings.open` state with `open/close/openSection`, and section targets |
| Native welcome notice with the shell ported | settings-shell | The welcome step (`ui-settings-models`) stores its acknowledgement in the `ui-settings-general` namespace, which only the native row serves; a Loader patch cannot change a row's module, so with the row off the namespace is unserved. Workaround: settings-shell ports the step and shadows it, keeping the acknowledgement in its own namespace | Let the welcome acknowledgement live in a namespace the settings base (`ui-settings`) serves |
| A panel's own icon on its tab | main-tabs | Only the `sidebar.panellist` declarer (the sidebar occupant) may `renderSlot` its entries; another plugin sees the entry's label but cannot render its icon | Let any plugin render a list entry read-only, or carry an icon descriptor in the entry options |
| Close the last tab to an empty main view | main-tabs | `selectPanel(null)` shows the retained Session; clearing the main view needs `startSession`, which creates (or reuses) a blank Session | A `layout.clearMain()` / `uiWorkspace.closeSession()` that releases the main view's Session reference |
| Draft attachments that survive leaving a thread and reloading | prompt-stash | The Conversation store persists only the draft text; draft attachments live in the session scope's input shell, and when the scope drops (leaving the thread releases its last reference) `shell.dispose()` hands the ids to `releaseDraftAttachment`, so files and images are lost on return or reload. prompt-stash retains the scope while the composer holds attachments, which covers in-app navigation but not a reload | Persist draft attachments with the draft (e.g. IndexedDB blobs plus upload receipts) and re-hydrate the rail when the shell is re-created |
| Send while an attachment uploads | send-after-upload | `installDraftKeymap` (`dsh-client-ui-conversation`) refuses Enter with a toast on Lexical's critical-priority `KEY_ENTER_COMMAND`, and Send is a disabled button; no slot, event or `matchEnter` (polled only for `/` drafts, after the upload guard) runs first. Workaround: a window `keydown` capture and a `pointerdown` capture on the disabled Send button (found by its CSS-module `_primary` class) | A composer submit guard that waits for pending attachments, or a `beforeSubmit` hook that may defer the send |
| Session references in sent messages as links | mentions | `projectUserText` (`dsh-client-ui-primitives`) renders session chips as inert spans (its `references` only open files and skills) and `UserStyleBubble` (`dsh-client-ui-chat`) renders "Referenced session · …" as text with labels only; `openReference` receives no pointer event. Workaround: mark the nodes `role="link"`, resolve labels from the thread's `session-reference` recall events, and read Mod from the last pointerdown | `references.openSession(sessionId, { newTab })` in `projectUserText`, session ids on the reference line, and the triggering event in `openReference` |
| Hide a plugin-made fork from thread lists | btw, thread-sidebar | A fork carries no plugin-writable marker (`SessionSummary` exposes title, parent and origin `subagent` only), so `/btw` forks are hidden by the title prefix `btw · ` | An `origin`/tag field a fork request can set, which list consumers can filter on |
| Archive a side chat when its tab closes | btw | `registerCloseHandler` exists only on the concrete `SidebarRightController`, not on the typed `ISidebarRight` face, so the plugin decodes it at runtime | Add `registerCloseHandler` to `ISidebarRight` |
| Jujutsu revision and bookmark references in sent messages as links | jujutsu | Native markdown renders inline code as inert `code`; no renderer seam lets a plugin claim a text token, and `openReference` only fires for composer chips the plugin itself inserted. Workaround: mark `code` nodes inside the Session's `[data-conversation-session]` subtree (`data-dshfiles-jj-reference`, `role="link"`) and delegate click/keydown, taking the bookmark names that make a word a link from the composer context query. Because the reader should see the bare name, the plugin also rewrites the code text node to drop the `jj:` prefix, and re-strips it after every React render (a text node that changed into something else stops being a link) | A message-text reference renderer, or an `openReference`-style callback keyed by a token grammar the plugin can extend |
| Keep a native cell's modal while moving its trigger | jj-integration | `@deepseek-ai/dsh-session-log-export` draws the header menu and the export progress modal in one `conversation.session.header.utilities` cell, so the plugin's own menu cannot take over the trigger without unmounting the modal. Workaround: shadow the cell at a lower priority, render only feedback there (a toast driven by the controller's store), and put the trigger in the plugin's own menu | Split the cell, or let a slot entry keep another entry's component mounted while it contributes its own UI |
| One global plugin stylesheet instead of a sheet copy per bundle | — (plugin-ui) | No plugin API to contribute a global stylesheet to the shell and no Host route for a static asset, so the shared sheet must be compiled into, and injected by, a client bundle. Workaround: `@dshfiles/ui-styles` is the one bundle that compiles and injects the ordered union sheet, so a class change rebuilds only it and the changed plugin; see [plugin-ui](../plugins/@dshfiles/plugin-ui/README.md). | A `styles` (or core-CSS) contribution point, or a Host-served asset route the shell loads once per boot |
| Per-session completion-unread state that every client shares | main-tabs, thread-sidebar | `UiSession` (`dsh-client-ui-session`) keeps `completionUnread` in per-tab memory: it adds an id when a session stops running and removes it when that tab's main view retains the session. Nothing durable or Host-side records "this turn finished and the user has not seen it", so a CLI, another plugin or a second tab cannot read the same state, and a page load starts empty. Workaround: `@dshfiles/thread-sidebar` owns a durable `thread_attention` domain plus the `thread-sidebar-attention` API (with the `thread_attention_state` agent tool), and publishes the contract as the `@dshfiles/thread-sidebar/attention-api` dshx module that `main-tabs` reads for its tab dot. | Upstream request: a supported Host-side per-session completion/acknowledgement fact (projection plus command) so every client and tool reads one truth. Not a core patch from this repository; the plugin-owned API above is what this repo ships until then. |
| Targeted running and pending-question lookup for rebasing | jj-integration | `SessionController.list` accepts only an empty request and enumerates every visible session; `inspect(sessionId)` reads a persisted event prefix but does not report whether that session is currently running. Rebase safety therefore requires a global session listing before the thread's JJ operations, and the plugin cannot replace it with a bounded per-thread query without weakening the guard. | Add a supported batch lookup for current running state and pending-question projection by requested session IDs. Retain the existing safety check until available. | |
| New thread shows its composer before `session/create` returns | thread-sidebar, jj-integration | The native New thread action keeps the previous Session's composer mounted until `session/create` resolves, then swaps it. Text typed in that window lands in the previous Session's draft and looks lost. Measured 2026-10-19: 80–310 ms on an idle scratch Host, 16 s on the live Host while its event loop stalled. | Open the new composer optimistically and bind it to the Session once created, or route keystrokes typed during creation into it |
| Move a blank Session's draft without its composer mounted | jj-integration | The native workspace picker moves draft, attachments and references only from the mounted composer, and `onPick` of an unmounted one moves nothing. A first send that isolates by default therefore loses its prompt when the user opens another New thread before the switch ends (see [first-send isolation race](performance-optimization/evidence/host-stall-profile-2026-10-19.md#first-send-isolation-race)). | A conversation API that transfers a Session's draft to another Session (or creates a Session in a workspace with a given draft) independently of the main view |
| Park and unpark a thread | thread-sidebar | Park is browser-local (`parkedSessionIds` in the plugin's settings namespace); the registry has archive and pin verbs only, so no other surface or Agent can move a thread to Parked | A registry park verb with its projection, folded into the sidebar's group model |
| Mark a thread unread | thread-sidebar | Unread and seen-completion markers live in browser `localStorage`; `SessionSummary` exposes `updatedAt` but no read-state field, so an Agent cannot mirror or clear the unread dot | A durable per-Session read-state field with a set/clear verb |
| Deliver a desktop notification | thread-sidebar | Notifications use the browser `Notification` API; the Host has no notify verb, so no plugin can raise an OS notification for an approval, a question or a finished thread | A Host notification service with a permission model, or an event a client surface turns into a notification |
| Open a UI surface (Settings, a panel, a thread, a file in the editor) | main-tabs, shortcuts, agent-toolkit, editor, jj-integration | Opening Settings, a sidebar panel, a main-view thread or an editor tab is client-only (`layout.selectPanel`, `uiWorkspace.openSession`, the private `ui-settings-general` store, `dshfiles:open-file` window events); no Host action opens a surface | A Host or dshx action contract for opening named surfaces, or an official command the shortcut and palette registries may run |
| Answer an approval, switch the permission preset, enter plan mode | native (dsh-user-approval, dsh-permission-presets, dsh-plan-mode) | The approval waterfall answers a Remote Event and has no RPC verb by design; permission presets expose `catalog` but no `set`; plan mode ships an exit tool but no enter verb — all three ride `commands/execute` | Scoped, human-approved write verbs per surface if writes are wanted; never an agent-answerable approval RPC |
| Delete a thread | thread-sidebar | No Host verb and no GUI control removes a Session; the registry's archive set is the only removal path, so "delete" cannot be built without inventing one | A delete verb only if permanent removal is ever wanted; until then archive is the product answer |

| Choose the next thread's host before it starts | multi-host | The Local/remote destination is a client stored value; no Host service reads or writes it, so an Agent cannot pick the machine a new thread runs on | A Host destination field on Session create, or a service owning the pending destination |
| One unreadable Session log fails every session-content search | memory, command-palette | `session-query-sqlite` reads every cold persisted log on each observation and a single unreadable one aborts the whole search with `SESSION_QUERY_PERSISTENCE_FAILED`, so Command Palette `#` thread-content search returns nothing after minutes. A log written by a plugin that disagrees with the format's read-time relationships (here an `llm/retry` row naming its fail-over target instead of the open `request/header` provider, plus an attempt number that skips its policy chain) is enough; the reader reports one violation at a time and never quarantines the file. Workaround: `@dshfiles/ai-accounts` writes valid rows now and the one bad log was moved to `~/.dsh/quarantine/`. | Skip a log that fails validation and report it as a typed per-Session diagnostic instead of failing the whole search. |
| Enable or disable a skill | native (dsh-skill) | `SkillRegistry` exposes list/get/snapshot only, with no enable/disable and no Remote verb, so a skill cannot be turned off for one Agent or one profile | A skill-enablement verb scoped to profile, workspace or Session |
| Browse and create folders in Add Workspace | workspace-folder-picker | Stock DSH 0.2.0-rc.2 does not ship the `hybrid` backend for the adaptive `directory-picker` Host service; the plugin's `remote.directoryPicker.list` and `createDirectory` flow requires that backend. No core patch in dshfiles. |
| Reliable `sessionQuery.searchSessions` under a moving corpus | memory, dshx (CLI) | The installed `@deepseek-ai/dsh-session-query-sqlite` allows only two corpus observations (`STABLE_OBSERVATION_ATTEMPTS = 2`) and `continue`s on any persistence-snapshot or live-session-set change, so a busy Host fails the search with `SESSION_QUERY_PERSISTENCE_FAILED` ("persistence observation did not stabilize after one retry"). The typed code is also lost across the core RPC: `@deepseek-ai/dsh-api-session-controller` rethrows it as `gateway/internal` and the caller only sees the message. Workaround: memory's `find_threads` and `dshx sessions search` retry the transient failure a bounded number of times, then return a labeled title/metadata/memory page with `degraded` provenance, and fail with the typed `search-unavailable` / `session-search-unavailable` code when nothing else matches. No false empty, no core patch. | Raise the observation budget (or back off between observations) in the SQLite backend, use bounded concurrent cold reads as row 14 asks, and preserve a `SessionQueryError` code across the session-controller RPC instead of collapsing it to `gateway/internal` |
| Bound and scope the Host's filesystem watches | dshx (Host-owned watches) | Every open `changes` target, skill file and config file owns its own chokidar `fs.watch`. A live Host with 39 thread workspaces, 146 Sessions and ~40 skills held 343 watchers — 233 under the thread workspaces, 83 under the read-only Nix store skills tree — and chokidar stats each path as events arrive, which was the busiest leaf in a CPU profile of the Host. No Host or profile setting scopes or caps them, and an immutable store path cannot change at runtime. | A watch budget or ignore setting (or a `ctx.fs.watch` scope option) that skips immutable paths, reuses one watcher per directory, and reports the open watch count |
| Virtualize long native transcripts | ADE performance audit | Core ChatView renders the native user/assistant transcript; dshx `conversation.chat.node` adds event-derived plugin nodes but cannot replace the message list or its viewport. The 100-turn scratch run reached 7,586 DOM nodes, p95 content visibility of 1,547.5 ms, and 333 observed long tasks, but end-to-end samples do not isolate transcript rendering as the cause | Expose a supported core-owned message-list/viewport renderer with virtualization and scroll-restoration semantics; retain Host history as source of truth. See [ADE interaction performance](../docs/ade-performance/README.md) |
| Keep the native main Conversation view warm across thread switches | thread-sidebar / native chat | `ISessions.retain` can pre-open Session history, but selecting another Session keys strict conversation content by Session generation and remounts its `conversation.view`. No public lifetime/cache or replaceable-main-transcript seam lets a plugin keep native ChatViews warm or virtualize the default transcript; only the semantic scroll anchor survives. | Add a bounded retained-view or main-transcript virtualization seam with stale-selection and scroll-anchor contracts. First test plugin-owned ArrowDown navigation with a small `SessionReference` lookahead; escalate only if warmed switches still miss 50 ms. No core patch or parallel history store. |
| Live test progress ("Running tests · 13 of 42") | test-runs | A foreground `bash` call's block carries no output until it settles (`terminalCardModel` gives a running card `output: undefined`), and no Tool progress event reaches a tool view, so the card cannot count finished tests while Vitest runs.
