## Remaining acceptance gates

1. **Human decision (open):** The user authorized Pi and VPS as candidate targets, with disk caution; no first target, SSH user, `DSH_HOME`, or existing service owner is selected. Choose these before migration. Current Nixfiles has macOS DSH Home Manager wiring and a Pi runner package, but the Linux workstation composition does not import a DSH service owner. The read-only VPS audit found no DSH unit/service in the registered home. Do not mutate the production Swarm or select an owner by assumption.
2. **Owner-side service:** implement the deterministic non-interactive service in the selected owner's repository. Pin the official DSH/Node/package-manager/dshfiles/profile/dependency tuple; set `PATH`, `DSHFILES_DIR`, `DSH_HOME` and loopback bind explicitly; prove profile-sync failure, stop semantics, restart/backoff and logout/linger behavior. Keep one service owner.
3. **Launch-token boundary:** the existing nixfiles supervisor fallback still needs owner-side fixes before it is accepted: force private permissions on both pre-existing `runtime/` and `web-url`, avoid writing tokenized `dsh web:` output to service logs, and remove stale metadata on all exit paths. Preserve the plugin's private `launch.json` behavior. Do not claim the fallback is safe based on static Nix configuration.
4. **Disposable Linux release proof:** use the selected disposable host to demonstrate boot/readiness, loopback-only access, wrong host-key/identity rejection, clean stop and crash recovery, pinned upgrade, and software rollback while preserving its DSH home, sessions and runtime identity. State data-migration/backup limits separately.
5. **Isolated SSH lifecycle E2E (partial):** a forced scratch browser E2E now boots a second DSH behind generated loopback sshd and verifies readiness, remote session create/list, and transcript cwd readback. Still open locally: tunnel loss/reconnect, stale launch metadata, failed profile sync, clean/crash cleanup, and mutation-response loss without replay. Keep physical-host acceptance manual and separate from CI.
6. **Safety invariant:** CI and scratch runs must not contact or restart a real host or the user's live DSH on `:3080`.

The manual SSH smoke is safer to invoke but is not service acceptance: it requires `MH_DISPOSABLE_TARGET=1`, `MH_ALLOW_REMOTE_MUTATIONS=1`, explicit `MH_SSH_TARGET`, private `MH_SSH_KEY`, `MH_KNOWN_HOSTS`, `MH_UNIT`, `MH_WS` and `MH_REMOTE_HOME`; optional `MH_SSH_PORT` is bounded to 1–65535 and defaults to 22. It disables per-user SSH config, refuses unknown host keys, and reads launch files rather than the journal. The separate transport test still tests only the strict SSH option builder against generated loopback sshd with ephemeral keys/known_hosts; the new scratch E2E adds local DSH operations but neither provides persistent service or release acceptance.

## Resume here

Continue the local fixture with tunnel loss/reconnect, stale metadata, profile-sync failure, clean/crash cleanup, and no-replay coverage. Separately wait for the selected target/service owner and disposable Linux proof environment before changing a service or recording upgrade/rollback evidence. Until those gates pass, leave this plan open and deployment acceptance unchecked.
