# Tool-heavy ingestion coding benchmark

## Why a fourth lane

The first three long scenarios chiefly evaluate pasted evidence, planning, recall, and one handoff artifact. They cannot reproduce a memory mode's coding deficit under repeated read/edit/test/debug tool chains. This independently authored fourth lane **builds** a small dependency-free fictional Node ingestion repository with a smoke-green but materially defective prototype, then requires real repairs, actual regression tests, persisted-state debugging, corrected requirements, and a release across three sessions. It is not a port of emisoup and contains no copied implementation or private data.

[Scenario module](scenarios/ingestion-coding.mjs) exports `createScenario({ rep = 1, variant = 'long' } = {})`. The result is an ordinary scenario with `fixture: 'ingestion-coding'`, `truth: {}`, and `acceptance: 'acceptance/coding-ingestion.test.mjs'`. **No compaction configuration exists.** The parent pipeline loads the module, validates packet fields, pairs repetition/variant, registers the fixture, and runs the ordinary scratch-host pipeline.

Long variant: **65 turns**, sessions **21 + 20 + 24**, **54 distinct tool-required work packets** over 18 boundaries and three stages. Each packet demands relevant source inspection, a real focused Node regression run, and repair or concrete verification. Stages are reproduce/repair, adversarial regression, and persisted rehearsal. They introduce different cases rather than asking the model to rewrite already-correct code gratuitously. Each packet includes eight realistic structured observations; replay traces deliberately include stale evidence, conflicts, throttling, late responses, and overlapping scope. These are pasted synthetic tool exports, while project reads, tests, edits, filesystem failure reproductions, and CLI runs are actual tool work.

Repetition 1 volume is **495,617 prompt bytes**, approximately **123,905 newly supplied input tokens** by UTF-16 characters / 4. Pilot is **29 turns**, 18 work packets with three observations each, **88,099 bytes**, approximately **22,025 input tokens**. These are corpus estimates, not tokenizer measurements or provider cost, and exclude assistant replies and real tool history. Native repeated context can exceed the corpus size substantially. Each session has its own context window; this corpus does not force natural compaction on a provider with a larger window. Record actual tool counts, provider usage, per-turn request sizes, and acceptance, not only recall scores.

Seed is `20670412 + rep * 1009`, with repetitions 1..10,000. Pair repetition 1/2/3 across modes; same variant and repetition yield byte-identical prompt corpus with `metadata.corpusSha256`. Different repetitions vary incidental replay observations, not the coding requirements or evaluator. Pilot retains amendments, fresh-session probes, executable acceptance, and final full review, but includes only six of the 18 boundaries in work packets. Pilot is a harness/tool-chain smoke lane, not proof of full long-horizon coverage; the final acceptance still evaluates the entire implementation.

## Project and behavioral ground truth

Public prototype consists of [store](fixtures/ingestion-coding/project/src/store.js), [ingestion loop](fixtures/ingestion-coding/project/src/ingest.js), [report](fixtures/ingestion-coding/project/src/report.js), [local CLI](fixtures/ingestion-coding/project/src/cli.js), [smoke tests](fixtures/ingestion-coding/project/test/smoke.test.js), a local example response file, and ordinary package/readme/changelog metadata. There are no dependencies. The public API is fixed in the template readme; the model may add helpers and tests but must repair the actual implementation and retain those exports. Prototype defects are intentional benchmark input, **not safe application code**.

The conversation's source contracts and corrections establish all evaluated requirements:

1. **Ownership:** exact `(organization, provider)` pair for records, checkpoint, complete marker, replay history, and reports. Valid scope identifiers match `/^[a-z][a-z0-9-]{1,63}$/`; invalid scope rejects `IC_INVALID_SCOPE`, without normalization into another tenant. External ids are opaque, nonblank strings up to 128 characters, and may legitimately be `__proto__`.
2. **Canonical rows:** enumerate `externalId`, `title`, `observedAt` only; title is a string and observation time is a finite ISO date-time. Validate the whole page before mutation. Invalid rows reject `IC_INVALID_RECORD`; duplicate ids within one page reject `IC_DUPLICATE_ID`. Scope/snapshot reads are defensive copies.
3. **Progress:** unseen scope starts at page 0. New page equals the selected durable nextPage; nextPage must equal page + 1, with nonnegative integer pages. Bad progression rejects `IC_CHECKPOINT_CONFLICT`. Commit rows plus progress together; revision increments once per accepted page.
4. **Replay:** identical canonical page/nextPage/done returns `replayed`, with current scoped counters, and does not mutate, increment revision, or rewrite bytes. A changed canonical replay rejects `IC_REPLAY_MISMATCH`. Transport-only fields do not change canonical identity. Replay persists across reopen and never regresses progress.
5. **Freshness correction:** initial arrival-order prototype is superseded in session two. Newer `observedAt` wins; older observations cannot regress canonical content, even though valid page progress still commits. Equal timestamps retain the existing row.
6. **Retry correction:** initial three-attempt/1000ms draft is superseded: **four total attempts**, including the first; default **90,000ms floor**; sleep is max(configured floor, finite nonnegative Retry-After seconds ×1000). Retry 429, 503, or transport exceptions on the same scoped page. No sleep after the final failure. Exhaustion is `partial/retry-exhausted`, never fabricated empty success. Configured maxAttempts is integer 1..10, maxPages integer 1..100, retryMinDelayMs nonnegative safe integer; invalid bounds reject `IC_INVALID_OPTIONS`.
7. **Partial outcomes:** permanent 400/401/403 → `partial/provider-permanent` with no retries or commits. `429 + quotaExhausted:true` → immediate `partial/quota` without sleep/fallback. Page budget without done → `partial/page-budget`. Successful terminal empty page is genuine completion. Preserve earlier records/progress on later failure and resume from committed checkpoint; already-complete scope fetches nothing.
8. **Cancellation:** check before acquisition, after a returned response before commit, and after retry sleep. Return `cancelled/aborted`, preserving earlier committed work; never apply a late response after cancellation. No rollback promise for an operation already durably published before cancellation.
9. **Filesystem/process boundary:** candidate state publishes after successful persistence, using temporary-file replacement rather than truncating live state first. A real filesystem refusal preserves prior in-memory state. Corrupt JSON or invalid persisted snapshot shape rejects `IC_CORRUPT_STATE` without overwriting original bytes. Concurrent commits on one openStore instance serialize; both different-scope results survive, identical same-page work commits once, and a failure does not poison subsequent queued work. **No multi-process writer locking, fsync, power-loss durability, or production database claim.**
10. **Report/release:** public summary is exactly `{organization,provider,nextPage,recordCount,complete,acquiredPages}`, selected scope only, with no raw rows. CLI reads local simulated responses and reports truthful complete/partial outcomes without network or real waiting. Final package version **0.2.0**, changelog covers **scope**, **retry**, and **partial** corrections; public tests remain runnable.

Exact recall ground truth: incident owner **Rae Thorn**, active organization **org-riverglass**, corrected defaults **four attempts / 90000ms**, freshness **newer observation wins**, release **0.2.0**. No paid fallback API hostname is established; negative recall requires `NOT_RECORDED`. There are two delayed recall probes, three fresh-session probes, and one negative probe. Existing substring scoring is only a coarse recall signal, not a substitute for code acceptance. Facts can be reinforced by earlier answers or persisted into legitimate source/docs, so memory-only probe turns expressly forbid filesystem and shell retrieval.

## Hidden acceptance and offline evidence

[Hidden acceptance](acceptance/coding-ingestion.test.mjs) loads the candidate's actual modules from `BENCH_PROJECT`, runs its public tests in a real Node subprocess, and independently evaluates isolation, typed refusals, canonical mapping, replay, whole-page atomicity, freshness, real filesystem failure, corruption, serial commit ownership, retry counts/delays, quota preservation, permanent failures, page-budget resume, cancellation, report scoping, and CLI stdout. It uses actual files and the declared injectable local provider/sleep seam, **not module mocks**. Test snapshots are cloned by the evaluator before mutation so a candidate's own alias bug cannot hide failure-atomicity defects. Hidden code and expected values are not copied into the model project.

[Offline scenario tests](coding-ingestion-scenario.test.mjs) prove deterministic corpus/seed behavior and volume, restricted probe scoring, fixture preparation and no clobber, executable prototype smoke/CLI, failure of hidden acceptance on the intentionally defective prototype, and success against the separately authored [reference store](fixtures/ingestion-coding/reference/store.js), [reference ingestion loop](fixtures/ingestion-coding/reference/ingest.js), and [reference report](fixtures/ingestion-coding/reference/report.js). They also reintroduce the prototype's real report scope bug into an offline verified candidate and require hidden acceptance to fail again. The reference is an **evaluator-only oracle**, not a fixture preparation option. Applying it to a temporary offline test candidate establishes that acceptance is achievable; it is never made available to a model run.

Focused offline evidence: **5/5 scenario tests pass**; prototype public smoke **2/2 pass** while hidden acceptance **24/25 fail**; repaired reference hidden acceptance **25/25 pass**; reintroducing the prototype report leak makes hidden acceptance fail again (**1 failure**). This rules out a vacuous always-green evaluator. Scope input type validation has one justified narrow lint exception at the dependency-free evaluator's raw-input boundary, before regex coercion; it is not a business-logic representation check or a new production dependency.

No paid model or matrix has been executed for this lane. Offline reference passing demonstrates fixture/evaluator viability, not model quality, cost, memory effectiveness, or a live provider integration. The parent owns paid-run scheduling and honest observed usage/reporting.

## Privacy, provenance, and isolation protocol

Architecture inspiration is the read-only, abstract source review documented in [long-scenario provenance](long-scenarios.md): declarative/runtime ownership and scoped ingestion/checkpoint/retry patterns. All project code, tests, API names, fictional identities, timestamps, response data, and documents here were independently authored. This relay restored the lane from its immutable WIP revision into its own workspace without editing that origin. No new inspiration reads, private dataset access, secret values, proprietary source copying, reference-repository edits, or live DSH changes occurred.

**Every session's first prompt** restricts coding reads/edits/tests to this scratch project's source, public tests, examples, and docs, allowing memory tools. It explicitly prohibits **DSH_HOME, DSH session logs/exports, host/runtime databases, process-environment discovery of host state, evaluator files, reference source, other runs/projects, and decompressing or reconstructing historical transcripts from disk**. Recall turns impose the narrower no-files/no-shell/no-network rule. `scoreProbe` enforces memory-only tool names (`memory_search`, `memory_zoom`, `memory_context`, `memory_status`) for delayed/cross-session/negative recall, and per-packet evidence records observed tool calls. Tool presence is instrumentation, not task success; hidden acceptance is the correctness gate. A native pilot elsewhere demonstrated that host transcript reconstruction can otherwise masquerade as memory success.

These are **prompt-level evaluation restrictions, not OS-enforced isolation**. Hidden/reference code is physically outside the prepared project but remains on the same host; inspect tool evidence before counting a run as valid. Project files are deliberately available on ordinary coding turns, because state persisted in repaired code/docs is legitimate coding context; host session logs are not. The scenario exercises same-project cross-session work and actual application organization/provider isolation. It does **not** prove OptMem cross-project memory isolation, which needs a separate multi-project driver lane.
