Owned fork of DSH's native Conversation client plugin. It preserves the full native shell, services, Slots and composer, while recognizing canonical session-reference wire text on paste and inserting it as a structured reference chip. Plain text is preferred; when only HTML is available, session-link anchors are converted to canonical mention text and other markup is reduced to safe text.

## Conversation header in Workbench

The original Header/SessionHeader and every contributed action render inside each fixed conversation's existing SessionProvider through the public Workbench conversation-header Factory contract. Rich Composer is its sole implementation and the sole declarer of the native header child. Native MainPanel calls the same Factory; Workbench no longer forces the Chat view, so the native per-session view store drives the existing body without replacing its editor. The Workbench-only host-corner clearance keeps tab-row recovery off the toolbar; native callers retain the original bare header. [Ownership and browser proof](../workbench/docs/conversation-header.md).

The native `conversation.composer.bar` slot requires package-private injection state (`ComposerBarInjected`) to provide its keyboard, uploads, notices, hooks and session input actions. That callback is created inside the native plugin and is not exposed as a reusable public service. A separate slot occupant cannot safely rebuild those props, so this fork replaces the whole `ui-conversation` Loader row while retaining its complete shell and service implementation. The stock row is disabled in this package's patch; other DSH core packages remain unchanged. Its composer Slot still registers at priority 0, so the higher-priority remote-composer takeover at -100 keeps its existing behavior.

## Thread views as thread-panel facets

The stage always shows **Chat**. Every other registered `conversation.view` (**Trajectory**, **Traces**, **Requests**…)
is a facet of the thread panel (productivity pass Q5, docs/ade-ux §4.4 "no sub-tabs in the header"): Rich Composer
registers one right-pane page type per view, with a guide entry, so it shows in the thread panel's guide and in every
Workbench pane's **Choose a view** (movable like any pane). The page body renders the view through the same
authorized `conversation.session` declarer as the Workbench view panels below, so a view's own requests (a turn's
**Trace** button, **Show in chat**) keep working and no second composer mounts. The
`@dshfiles/rich-composer/thread-views` dshx module lists the views (`ThreadViewsModel.list`) and opens one for a thread
(`ThreadViewsModel.open`); thread-sidebar's header **More thread actions** uses it for **Open Trajectory / Traces /
Requests**. The header title never truncates before its chips: they shrink first and leave from the start edge, so the
`⋯` goes last.

## Workbench Conversation views

In Workbench mode, **Add panel** offers each registered non-chat view for known threads (for example, **Trajectory — thread title**). Each mounted panel retains its own explicit Session and releases it when closed. Renaming only changes the label, not the component identity. A failed acquisition shows an error rather than borrowing the active thread.

The root assembly declares only its own session-scoped child. That child calls the public `conversation.content` Factory with a fixed-view local component. The original `conversation.session` still renders `conversation.view` with its genuine store, hooks and owner props. An owned context wrapper renders just the Factory's Views in these panels, with no hidden composer or bootstrap conversation. Sources exist before any conversation mounts, so restored layouts do not depend on a previously captured renderer. The normal native Conversation Factory is unchanged outside this explicit wrapper context.

## Embedded editor

The `@dshfiles/rich-composer/rich-text-editor` dshx module creates a separate native composer editor runtime and DOM
root for each occurrence. Its owner supplies its value, node registration, projection and file handling; it retains
submission, persistence and domain-specific completion. Backlog uses it for item bodies and replies without borrowing a
thread's editor or draft. The fork's `runtime.ts` accepts owner node types and `ComposerContentEditable.tsx` exposes the
bound element to the owner; both remain declared in `native-fork.json`.

## Paste behavior

The upstream editor handles clipboard `text/plain` as editable text. This fork parses canonical `@[label](dsh-session:<base64url>)` values in that text and inserts each through the native session-scoped reference action, preserving surrounding text and selection. Unsupported or invalid wire values remain ordinary text. HTML clipboard data is never inserted into the DOM; when plain text is absent, it is reduced to text and valid `dsh-session:` anchors are converted to the same canonical wire format.

## Prompt recall

ArrowUp in an empty composer shows this thread's previous prompt; ArrowUp again goes older, ArrowDown goes newer and past the newest returns to the empty draft, and Escape brings that draft back at once. A multi-line prompt keeps ArrowUp/ArrowDown for its own lines until the caret reaches its first or last line. Editing the recalled text ends recall. The prompts come from the thread's loaded event window (`user/message` events from a person, newest first, each text once), so nothing new is stored and prompts outside the loaded history are not offered.

## Large paste

A paste of 32 KiB or more of text becomes a `pasted-<date>-<time>.txt` file attachment through the same upload path as a picked file, instead of filling the draft. A notice above the composer offers **Paste as text**, which removes that attachment and inserts the text as an ordinary paste. Continuable subagent composers, which accept only images, keep the text inline.

## Composer contract

The fork provides dshx's `Composer` contract (`src/composer-service.ts`) over its per-session input shells, so other plugins read and edit the draft, add chips, pick the model and move focus without a slot of their own. Quote, note, terminal-excerpt and line-comment chips are reference chips of the `composer-snippet` input-trigger source (`src/composer-snippets.ts`): the chip carries its content in `ref`, so a restored draft still sends it, and the model reads a quote as a Markdown block quote, a note inside `<note>` tags, a terminal excerpt inside `<terminal-excerpt>` tags and a comment inside `<comment path lines>`. A terminal excerpt's label is the terminal line range it came from (`Terminal 12-14`), and activating the chip reveals the captured output the draft holds. File chips use the native `reference` source the composer's file drop already uses. A plain-text draft whose serialized references still name chips (`[Image 1]`, `b:<ref>`, `@{handle}`, a file or thread mention) is turned back into those chips with `restoreReferences()`: every trigger source's `restore` grammar supplies the spans and the draft text itself is unchanged. `setModel` goes through the `modelDirectories` service, the same path as the model picker.

## The composer bar

One calm card (composer redesign b:v9yh): a 44px text
line that grows, "Ask anything" with a muted "@ mention · / commands" while the draft is empty, and one bar row in two
packed groups. Left: **+** (add files, run commands; `/annotate` points at UI) and the **mode chip**. Right: **⋯**
(undo, history, saved prompts, side question, Point at UI…), the model as plain text ("gpt-6-luna · high"), the
context ring from 25%, then Send.

The mode chip reads plan mode and file access in plain words ("Can edit", "Read only", "Full access", "Plan · Can
edit") and opens one menu with a Mode section (Standard, Plan) and a File access section, one sentence per choice. The
two are separate Host settings with no combined API, so the chip writes each through its own command (`/plan`, `/plan
off`, `/permission <preset>`), reads the catalog from the `permissionPresets` Remote and keeps the native risk
confirmation for Full access and Auto review. The native picker's labels cannot be overridden (the locale registry
refuses a second dictionary for its namespace), so the chip takes its seat; without the Remote the native seats stay.
In the new-thread bar the agent preset and the chip sit side by side under one hairline.

## Composer settings

`hidePermissionSelector` (Plugins page, off by default) hides the permission mode selector, the mode chip included. The
seat is a single Slot: the mode chip holds it at priority -1, and an empty occupant at -2 shadows it while the setting
is on and is disposed when it turns off; the change applies live.

## Updating from DSH

When the installed DSH package changes:

1. Compare the entire upstream package (`src/client` and `src/submission-settings.ts`) at the exact new release commit against the pinned revision above; the table lists the only files that should differ.
2. Re-apply the local delta on top of the new upstream files rather than porting your own edits forward.
3. Recheck the Loader row identity, native service dependencies, slot props/priorities and plugin peer ranges against the installed release.
4. Update package pins, source revision and this document together; run typecheck, tests, build, import check, boot check, and the paste browser journey. Never overwrite the fork from upstream without reviewing its diff.

## Phone thread menu

On a phone the conversation header gives up its title row: a 44 pt bar portalled into the shell's top bar holds the
Changes pill and one `⋯` button, and `⋯` opens a bottom sheet with the thread's header actions and utilities (visual
refresh T3.5, productivity pass Q6). Only the conversation whose own header seat is on screen portals its bar, so
kept-alive threads never stack bars. Trajectory, Traces and Requests are thread-panel facets (Q5), so the sheet has no
view switch.

The typed dshx module [`phone-thread-menu`](src/phone-thread-menu.tsx) (upstream #76) owns the reader/tool contract
and its open state ([`phone-thread-menu-service.ts`](src/phone-thread-menu-service.ts)). In this fork the sheet is its
reader and, while its bar is on screen, its launcher: composer plugins that call
`usePhoneThreadTool({ id, label, open, active, available })` (side question, saved prompts, annotations) hide their
control in place and appear as 44 px rows in the sheet; a pick closes the sheet and calls the owner's real `open`.
Without the contract the sheet keeps its own open state and every control stays where it is. Opening focuses the
sheet; Tab stays within it, Escape and the scrim close it and return focus to the opener. Upstream's top drop-down menu
with View / Thread / Composer sections and its phone tab strip are not used in this fork (merge 2026-11-11).
